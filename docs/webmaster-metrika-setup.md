# Яндекс.Вебмастер ↔ Метрика: что нужно нажать руками

Всё остальное по SEO делают скрипты в этом репозитории. Здесь — три настройки,
которые можно сделать только в интерфейсе Яндекса. Занимает минут десять,
делается один раз.

Сайт: `https://абхазберег.рф`
Счётчик Метрики: **108214677**

## 1. Привязать счётчик Метрики к Вебмастеру

Зачем: Яндекс начинает узнавать о новых и изменившихся страницах из данных
Метрики, не дожидаясь планового обхода. Новые объекты и статьи попадают
в поиск быстрее.

1. Откройте [Вебмастер](https://webmaster.yandex.ru/) и выберите сайт
   абхазберег.рф.
2. Слева: **Настройки → Привязка к Метрике**.
3. Выберите счётчик **108214677** и нажмите «Привязать».
4. Там же включите пункт про **использование данных Метрики для обхода
   сайта** (формулировка может называться «Обход по счётчику Метрики»).

Проверить: через сутки в разделе «Индексирование → Обход страниц» источником
обхода начнут появляться страницы, найденные через Метрику.

## 2. Подключить Telegram-бота Вебмастера

Зачем: уведомления о проблемах (страницы выпали из поиска, недоступен сервер,
появились ошибки в разметке) приходят сразу, а не при следующем заходе в
интерфейс.

1. В Telegram найдите бота **@YandexWebmasterBot**.
2. Нажмите «Старт» и авторизуйтесь тем же аккаунтом Яндекса, под которым
   заведён сайт.
3. Выберите сайт абхазберег.рф и включите уведомления.

## 3. Проверить, что цели Метрики на месте

В коде сайта уже отправляются цели: `click_whatsapp`, `click_telegram`,
`open_hotel_card`, `home_search_submit`, `blog_catalog_cta_click` (переход из
статьи блога в каталог).

В Метрике: **Настройки → Цели → Добавить цель → JavaScript-событие** и указать
идентификатор цели ровно так, как он написан выше. Без созданной цели событие
приходит, но в отчётах не показывается.

## Что делают скрипты (руками не нужно)

| Скрипт | Что делает |
| --- | --- |
| `tools/audit_yandex_webmaster_seo.py` | Дубли title/description, canonical, og:image, JSON-LD, сверка с sitemap |
| `tools/webmaster_recommended_pages_check.py` | Здоровье важных страниц: код ответа, скорость, title, canonical |
| `tools/apply_unique_page_descriptions.py` | Уникальные описания на страницах объектов |
| `tools/apply_noindex_to_hidden_pages.py` | Закрывает от индексации скрытые и осиротевшие страницы |
| `scripts/apply_blog_schema_extras.py` | publisher, FAQPage и HowTo в статьях блога |
| `scripts/inject_blog_related_links.py` | Блок «Читайте по теме» и кнопка перехода в каталог |

Первые два запускаются в GitHub Actions: аудит — вручную, проверка страниц —
каждые 6 часов вместе со smoke-тестом прода.

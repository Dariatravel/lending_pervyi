# Правила совместной работы: Cursor + Codex

Этот файл нужен, чтобы Cursor не перетирал изменения Codex, а Codex не удалял изменения Cursor.

## Цель

Мы работаем над одним сайтом параллельно, но с разделением зон ответственности.

- `Codex` отвечает за:
  - фильтры;
  - таблицы, JSON, CSV, XLSX;
  - данные каталога;
  - логику поиска;
  - JavaScript-логику;
  - генерацию и синхронизацию данных;
  - технические скрипты в `scripts/`.

- `Cursor` отвечает за:
  - визуальный дизайн;
  - компоновку блоков;
  - типографику;
  - отступы, размеры, сетки;
  - карточки объектов;
  - внешний вид форм;
  - адаптивность интерфейса;
  - чистый HTML/CSS фронтенд без изменения бизнес-логики.

## Главное правило

Нельзя удалять, переписывать или упрощать чужие изменения, если не было прямого запроса.

Если в файле уже есть логика, которую писал другой инструмент, её нельзя "почистить", "упростить" или "пересобрать заново" без проверки, за что она отвечает.

## Разделение зон

### Codex может менять

- `scripts.js`
- файлы в `scripts/`
- данные и сиды
- Supabase-скрипты
- логику фильтров
- преобразование таблиц
- импорт/экспорт данных
- служебные JSON-файлы

### Cursor может менять

- визуальные блоки в `index.html`
- CSS-слои и стили
- карточки каталога и страницы объекта с точки зрения дизайна
- адаптивность
- тексты интерфейса

### Cursor не должен менять без отдельного запроса

- логику фильтров;
- `id`, `data-*`, `name`, `for`, `aria-*`, если они уже используются скриптами;
- обработчики поиска и каталога;
- структуру, на которую завязаны `scripts.js` и фильтры;
- скрипты в `scripts/`;
- файлы данных;
- Supabase-логику;
- генераторы страниц.

### Codex не должен менять без отдельного запроса

- общий визуальный стиль сайта;
- типографику и композицию блоков "ради удобства";
- дизайн карточек, hero, секций и отступов, если задача не про дизайн;
- декоративные решения Cursor.

## Правила для общих файлов

У нас есть общие файлы, которые особенно опасны:

- `index.html`
- `styles.css`
- `scripts.js`

Поэтому:

### Если Cursor работает в `index.html`

Он может:

- переставлять визуальные блоки;
- улучшать тексты;
- добавлять новые секции;
- улучшать HTML-структуру для дизайна.

Он не может:

- удалять элементы фильтров;
- менять `id` существующих форм и кнопок;
- менять структуру каталога, если на ней висит JS;
- удалять классы/атрибуты, которые уже используются логикой.

### Если Cursor работает в `styles.css`

Он может:

- менять визуал;
- делать адаптив;
- улучшать сетки, карточки, формы, типографику.

Он не должен:

- добавлять стили, которые ломают функциональность фильтров;
- скрывать рабочие элементы фильтров и форм;
- делать глобальные сбросы, которые ломают существующую JS-логику.

### Если Cursor видит `scripts.js`

Он должен считать этот файл зоной Codex.

Разрешено только:

- читать;
- понять, какие `id`, `class`, `data-*` нельзя ломать.

Запрещено:

- переписывать обработчики;
- удалять функции;
- менять загрузку каталога;
- менять логику фильтрации.

## Безопасный процесс работы

Перед любой сессией:

1. Сначала посмотреть `git status`.
2. Если уже есть несохранённые изменения другого инструмента — не трогать их без проверки.
3. Если задача про дизайн — работать только в визуальной зоне.
4. Если задача про фильтры и таблицы — не трогать визуальную композицию без необходимости.

## Как работать без конфликтов

### Вариант работы по умолчанию

- `Cursor` делает дизайн.
- `Codex` делает фильтры, таблицы и логику.

### Если задача затрагивает один и тот же файл

Использовать правило:

- Cursor меняет только HTML/CSS-представление.
- Codex меняет только JS-логику и данные.

Если для дизайна нужен новый элемент:

- Cursor добавляет только новый контейнер, класс или обёртку;
- существующие `id` и `data-*` не удаляет.

Если для логики нужен новый хук:

- Codex добавляет минимально нужный `id` или `data-*`, не ломая визуальный слой.

## Что делать, если в файле уже много изменений

Если файл сильно изменён и непонятно, какие куски чьи:

- ничего не удалять;
- не переписывать файл целиком;
- работать точечно;
- сохранять существующую структуру;
- при сомнении оставить комментарий в задаче, что файл смешанный и нужен осторожный edit-only режим.

## Текущее рабочее соглашение

С этого момента:

- `Codex` ведёт:
  - фильтры;
  - таблицы;
  - поиск;
  - JS-логику;
  - служебные скрипты;
  - импорт/экспорт данных.

- `Cursor` ведёт:
  - редизайн;
  - HTML/CSS;
  - UX-композицию;
  - карточки объектов;
  - адаптивность интерфейса.

## Готовое задание для Cursor

Ниже текст, который Cursor должен воспринимать как рабочую инструкцию.

---

Ты работаешь только в зоне дизайна сайта.

Твоя задача:

- улучшать визуальный дизайн сайта;
- править HTML/CSS;
- улучшать композицию блоков;
- усиливать первый экран, карточки объектов, отступы, сетки, типографику и адаптивность;
- делать интерфейс современным, чистым и понятным.

Важно:

- не трогай бизнес-логику;
- не переписывай `scripts.js`;
- не удаляй существующие `id`, `data-*`, `name`, `aria-*`, если не уверен, что они нигде не используются;
- не ломай фильтры, поиск, каталог и загрузку карточек;
- не меняй файлы данных;
- не трогай Supabase-скрипты и служебные генераторы.

Зона Codex:

- фильтры;
- таблицы;
- данные;
- `scripts.js`;
- папка `scripts/`;
- логика поиска и каталога.

Твоя зона:

- `index.html`;
- `styles.css`;
- визуальные HTML-блоки;
- адаптивность;
- тексты интерфейса;
- карточки объектов;
- hero;
- UI-структура лендинга.

Если нужно добавить новый визуальный блок:

- добавляй новые классы и контейнеры аккуратно;
- не удаляй существующие элементы, на которых может висеть JS.

Если видишь спорный участок:

- не переписывай файл целиком;
- меняй точечно;
- сохраняй совместимость с текущей логикой.

Текущий приоритет:

- делать современный дизайн уровня сильных travel-лендингов;
- улучшать UX для семей, пар и туристов, которые едут в Абхазию впервые;
- снижать тревогу перед бронированием через структуру, тексты и визуальную ясность;
- вести пользователя к заявке мягко, но понятно.

## Короткая версия правила

Cursor:

- да — дизайн;
- нет — логика.

Codex:

- да — логика и данные;
- нет — самовольный редизайн без запроса.
